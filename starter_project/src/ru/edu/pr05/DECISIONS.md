# Решения по Практической работе №8 (Вариант 6)

## 1. Отказ от сеттера статуса
В исходном коде был метод setStatus, который позволял перевести заявку из любого статуса в любой. Я удалил его. Вместо него реализованы доменные методы submit(), approve(), reject(), cancel() и complete(). Это защищает объект от недопустимых переходов (например, из DRAFT сразу в APPROVED). При недопустимом переходе выбрасывается IllegalStateException.

## 2. Дополнительная проверка даты (вариант 6)
В методе complete() реализовано правило: завершить командировку можно только из статуса APPROVED и при условии, что с даты окончания прошло не менее 35 дней. Я вынес это число в константу MIN_DAYS_AFTER_END = 35. Это позволяет легко изменить бизнес-правило (если преподаватель попросит на защите), поменяв только одну цифру в одном классе.
